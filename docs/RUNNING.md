# 本地完整版本使用指南

## 启动

克隆后先运行 `setup.ps1` 安装依赖、构建前端并下载本地模型，再启动服务：

```powershell
.\setup.ps1
.\start.ps1
```

打开 [知序入口](http://127.0.0.1:8000)。[员工登录](http://127.0.0.1:8000/employee/login)与[管理员登录](http://127.0.0.1:8000/admin/login)分开。首次运行依次创建申请管理员、复核管理员两个独立账号（账号至少 3 位英文/数字，密码至少 10 位），没有默认生产账号。按 Ctrl+C 停止服务。`start.ps1 -NoBrowser` 只启动后端。脚本只绑定环回地址。

升级旧版本无需重新导入资料：启动时自动进行增量迁移，保留账号密码、文库、文档、片段、向量、会话及问答记录。已有员工保持已审核，旧成员关系默认查看权限。已有单管理员使用原账号登录，在「管理员变更」补设第二位管理员并选择职责；此操作不重置原账号。已有两位或以上管理员按创建顺序确定初始申请与复核职责，后续职责调整走复核流程。迁移前建议按下文备份整个 `data/`。

如果电脑的执行策略阻止脚本，可对本次进程使用：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
```

换电脑或重建依赖时运行 `setup.ps1`，需要 Python 3.12+、Node.js 20+、可用的 npm 和网络。首次下载模型权重约 1.15 GiB，CPU 即可运行，建议至少 8 GB 内存。Python 依赖在 `requirements-lock.txt` 锁定，npm 使用 `package-lock.json`。`setup.ps1 -SkipModels` 可先准备环境，随后执行 `scripts/prepare-models.ps1`。

## 密钥与生成服务

启动脚本读取 Windows **当前用户级** `AIHUBMIX_API_KEY`，优先于继承的进程变量。密钥只进入后端进程，不写 `.env`、代码、文档、日志、SQLite 或前端构建。当前密钥是否配置只返回布尔状态。

需要配置时运行 `scripts/configure-key.ps1`，在遮蔽输入中粘贴密钥，再重新启动服务。该脚本将密钥保存为你指定的 Windows 用户级环境变量。

生成服务固定使用 `https://aihubmix.com/v1/chat/completions` 与 `coding-kimi-k3-free`。当前问题和最多 6 个片段（各最多 500 字）会送至 AIHubMix；完整文件、历史对话、账号标识和文件名不发送。原始文件、本地索引和重排始终留在本机。

本机限制 5 请求/滚动分钟、100 请求/滚动 24 小时，并为每天 100 万 token 配置保守的 token 预算。额度持久化，重启不清零。队列最多 20 个问题。上游 429 触发冷却，保留问题和证据；上游共享账号在其他应用消耗的额度无法在本机提前获知。

**AI 有据问答**让模型挑选直接支持问题的原文，后端逐项验证 source ID 和连续引用内容，再通过 SSE 返回。因此首版输出以可验证的原文摘录为主，避免生成无法验证的改写或推论。**本地证据摘录**明确标为未调用生成模型，可在无密钥或断网时演示检索。未配置密钥的 AI 模式会明确显示模型不可用，不冒充生成成功。

## 使用流程

1. 员工在员工登录页申请账号；待审时不能登录。管理员在「员工注册」批准申请，并选择文库授权，也可直接在「成员账号」创建员工。
2. 管理员在「文库管理」维护文库、目录与文件；直接上传的文件立即进入处理队列，状态为「可检索」后参与问答。
3. 「文库授权」按成员设置「查看」或「查看与提交资料」。查看可浏览和提问；提交可在员工门户上传待审资料。未授权文库不会出现在浏览、搜索、问答或引用中。
4. 员工通过文库目录、统一搜索、标题/正文筛选、文件格式筛选、个人收藏及最近查看查阅资料。正文搜索覆盖已解析内容，支持连续关键词匹配；扫描图片不在正文搜索范围内。
5. 员工在「我的提交」追踪资料；管理员在「资料入库审核」下载原文件、批准或驳回。批准前文件只留在待审区，不解析、不创建文档索引、不参与问答；批准后开始解析，员工可搜索并提问。
6. 「问问知序」保留 AI 问答、证据摘录及个人问答历史。点击引用打开原文并高亮位置；PDF 可打开原始页，Office 文件可下载核对版式。管理员可切换员工门户使用问答。
7. 申请管理员在「管理员变更」提交身份、启停或职责调整；复核管理员审批。两位管理员均可直接进行日常知识管理，管理员身份变化不能通过普通账号接口绕过复核。
8. 初次体验可点「导入虚构演示」：创建 7 个文库、20 个目录及 32 份资料，含六种格式。旧演示可增量更新，保留文库与文档 ID、成员关系；只有同名虚构文件会更新并重新索引。不会创建演示账号，也不会自动向员工授权。

六种格式：PDF、DOCX、XLSX、PPTX、TXT、MD；每文件最多 25 MB，每文档最多 4000 个片段。PDF 定位到页，DOCX/TXT/MD 到段，DOCX 表格到表与行，XLSX 到工作表和单元格范围，PPTX 到幻灯片。XLSX 使用缓存值，未缓存的公式不作为可检索文字。不做 OCR：无文字 PDF 标记「需要 OCR」，混合 PDF 保留可提取页并提示无文字页。加密或损坏文档明确标记解析失败。

同库按 SHA-256 识别重复文件；删除会级联移除片段和向量；重新索引先清空旧索引，再原子写入新版本。删除、重建索引或撤销授权后，历史回答的旧引用会隐藏。

## 检查与评估

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe scripts\evaluate.py --username 你的账号 --dataset evaluation\demo.json
```

评估程序遮蔽输入本机账号密码，不读取 AIHubMix 密钥，使用本次账号权限下的真实本地检索。输出 Recall@6、Precision@6、MRR@6、延迟与指定拒答/冲突状态；原文位置作为相关性标签。真实资料可按 `evaluation/demo.json` 的结构新建标注集。

测试使用隔离临时 SQLite 和真实向量/重排模型；外部 API 响应被模拟。见 [验收说明](ACCEPTANCE.md)。虚构样例不能代表真实企业资料上的准确率。

## 本机运维

`data/knowledge.db` 保存账号、成员授权、目录、收藏、最近查看、提交审核、管理员变更、索引、问答、限额和不含正文的操作审计；`data/uploads/` 保存入库原始文件，`data/submissions/` 保存待审及已审核提交原件。停止服务后一起备份整个 `data/`；恢复时先停止服务，用同一次备份恢复数据库与文件目录，再启动。模型可重新下载，但改变 embedding revision 后必须重新索引资料。

服务重启会恢复待处理的文档；中断的问答标记「任务已中断」并保留问题，可手动重试，不会悄悄重复消耗模型额度。默认单个 Uvicorn worker；不要使用 `--workers` 或多实例共享同一目录，进程内队列与授权/外部发送锁按单实例设计。

开发前端：在 `frontend` 执行 `npm run dev`，Vite 将 `/api` 代理到本机 8000。交付使用静态构建与后端同源，cookie HttpOnly/SameSite 严格模式，写入请求带同源标记及 Origin 校验。密码用随机盐 scrypt；会话只保存令牌摘要；账号停用后立即失效。API 分组及数据流见 [DESIGN.md](DESIGN.md)。

本机首版不包含部门层级、多租户组织、自动 OCR、分布式队列或高可用。SQLite 内的向量用授权子集的 NumPy 精确余弦检索，适合小型本机知识库；大规模部署需要针对真实语料与容量重新评估索引和架构。
